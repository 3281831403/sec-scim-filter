sec-scim-filter
====================

用户目录对外提供按过滤表达式检索的能力，表达式直接来自查询串，攻击者可以改写它，若解析与求值对同一段文本理解不一致，越权读取与条件注入就会发生：契约要求记号化后每个记号给出种类与文本，属性路径保留调用方书写的大小写，字符串字面量把反斜杠转义还原成原字符，只有引号与反斜杠可以被转义，其它转义与未闭合的引号都是错误；语法树用带标签的元组表示，比较节点形如 ("compare", 属性路径, 运算符, 字面量)，存在性判断的字面量为空值，逻辑节点形如 ("and", 左, 右) 与 ("or", 左, 右)，取反节点形如 ("not", 子节点)；优先级从高到低依次为取反、与、或，同级左结合，括号改变结合方式，括号不配对必须报错。求值时属性名逐段大小写不敏感地匹配，属性缺失与显式空值必须区分：缺失时一切比较都不成立，显式空值可以与空值字面量相等且不满足存在性判断；文本比较大小写不敏感，数值按数值大小比较，两侧不可比时结果为假；生成 SQL 时用户值一律进入参数列表，占位符与参数顺序严格对应，不得把值拼进语句；校验只做结构检查并返回问题代码，不抛异常。不变量：同一语法树序列化后再解析得到同一棵树；给同级子表达式补上不影响优先级的括号不改变求值结果；多值属性上任一元素满足比较即视为满足。
